# REVIEW.md

Review of the starter `app/main.py`. "Fix" = what the submitted `app/main.py` does now.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Created without `tz_aware`, so every datetime read back is naive. Naive values silently mix with local-time values. | `punch_in - aware_dt` raises `TypeError`; instants shift by the server's UTC offset. | `MongoClient(..., tz_aware=True, tzinfo=UTC)`; all instants are aware UTC and are converted to epoch ms only at the API edge. |
| 2 | `punch_in`, `create_employee` (`datetime.now()`, `datetime.fromtimestamp(ms/1000)`) | Uses the **server's local zone**, not IST/UTC, and keeps microseconds (R1 wants whole seconds). `punched_at=0` is treated as "missing" (`if body.punched_at`). | Run the server in UTC and punch in at 23:30 IST: the stored `date` is the wrong day. `punched_at=1783312500.9` style values leak sub-second parts. | `ms_to_dt()` = `fromtimestamp(ms // 1000, tz=UTC)`; `now_utc()` truncates; `attendance_date()` computes the IST date (R1) incl. overnight shifts. |
| 3 | `PunchInIn` / `EmployeeIn` | No validation: `punched_at` accepts seconds, floats, negatives, huge numbers (`fromtimestamp` then raises -> 500); `status` is a free string (`ABSENT`, `"x"` accepted); `emp_code`, email, shift format, `joined_on` and `shift_start == shift_end` unchecked. | `POST /attendance/punch-in {"status":"ABSENT"}` returns 201; `punched_at: 1e20` returns 500. | Pydantic models: `StrictInt` bounded to the contract range, `Literal` status, regex patterns, real-date check, shift validator -> 422. |
| 4 | `compute_late_minutes` | (a) `int(total_seconds()/60) > 10` floors **before** comparing, so 09:40:01 (10 min 1 s) gives 0 instead of 10 and 09:40:00-09:40:59 are all "not late" whereas the rule is "strictly more than 10:00 s". (b) Builds `shift_start` on the punch-in's own (UTC/naive) date and zone, not IST. (c) No overnight handling. | Shift 09:30, punch-in 09:40:01 -> expected 10, got 0. Punch-in 09:30 IST on a UTC server compares against 09:30 UTC. | Compare in seconds (`> 600`), then floor to minutes since shift start; start instant is built in IST from the record's attendance date (`shift_bounds`). |
| 5 | `compute_work_hours` | Python `round()` is banker's rounding on a binary float (R4 wants half-up); no truncation. | 0.005 h, 4.505 h style values round the wrong way. | `Decimal(seconds)/3600` quantised with `ROUND_HALF_UP`. |
| 6 | `compute_overtime` | No 30-minute minimum (R3); ignores overnight shifts (end is always on the same date); `datetime.fromisoformat(date).replace(tzinfo=IST)` is aware while `punch_out` is naive -> `TypeError`. It is also never called by any endpoint. | 10 minutes after shift end returns 10 instead of 0. Any overnight record. | Rewritten on `shift_bounds()` (end falls on the next day for overnight shifts); returns minutes only when >= 30. |
| 7 | `/health` | Always returns `ok`, even if MongoDB is down. | Stop Mongo; `/health` still 200. | Pings MongoDB; 503 on failure. It also retries index creation if startup could not reach Mongo. |
| 8 | `create_employee` | Check-then-insert race, no unique index: two parallel POSTs can both pass `find_one` and create duplicates. `created_at` is returned as a datetime, not epoch ms. | 20 parallel POSTs with the same code -> several 201. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` -> 409. `created_at` returned as epoch ms. |
| 9 | `list_employees` | `skip = page * page_size` skips the whole first page; `total` counts the **entire collection** instead of the filter; no sort (contract: `emp_code` asc); `page=0`/`page_size=-1`/`page_size=10**9` unvalidated (negative skip raises -> 500). | `GET /employees?department=HR` shows `total` of all employees; page 1 starts at the 21st row. | `skip=(page-1)*page_size`; `count_documents(filter)`; `sort("emp_code")`; `Query(ge=1)`, `page_size` 1..100; index `(department, emp_code)`. |
| 10 | `punch_in` | `emp` can be `None` -> `emp["shift_start"]` raises `TypeError` -> 500 for an unknown employee (contract: 404). | `POST /attendance/punch-in {"emp_code":"NOPE"}` -> 500. | Explicit 404. |
| 11 | `punch_in` | Check-then-insert race: no unique index on (`emp_code`, `date`). | Two simultaneous identical requests both return 201 and create two records. | Unique index `(emp_code, date)`; insert and catch `DuplicateKeyError` -> 409. |
| 12 | `punch_in` response | Returns an `id` (the ObjectId string) and raw datetimes; `_id` must never be exposed, instants must be epoch ms. | Response contains `"id": "66f..."` and ISO-ish datetimes. | `record_out()` serialises every record: no `_id`, ms instants, defaults for missing fields. |
| 13 | `list_attendance` | `list(find(q))` loads the whole matching collection into memory, sorts and paginates in Python; sort has no `emp_code` tiebreaker, so pages are not stable; `total` computed from the in-memory list. | ~100k records: seconds per request and large RAM. Rows with the same date can swap between pages. | Server-side `sort(date desc, emp_code asc).skip().limit()` backed by an index; `count_documents` for the total (`estimated_document_count` when there is no filter). |
| 14 | `list_attendance` | `page=0` gives a negative slice start (returns wrong rows); `page_size` unbounded; `status` free-form; `date_from > date_to` not rejected; date strings not validated; leaks `id`/`_id`; legacy records without `history`/`half_day` are returned as-is. | `GET /attendance?page=0`; `?status=banana`; `?date_from=2026-07-09&date_to=2026-07-01` returns 200 with nothing instead of 422. | `Query` bounds, `Status` enum, strict date parsing, 422 for inverted range, `record_out()` fills defaults. |
| 15 | Whole file | No index is created anywhere (only `_id`). | `explain` shows COLLSCAN for every query. | `ensure_indexes()` in the lifespan hook (idempotent `create_index`); see DECISIONS.md. |
| 16 | Whole file | Mongo errors are uncaught -> 500 with a stack trace. | Stop Mongo and call any endpoint. | `PyMongoError` handler returns 503. |

**Looked at and judged fine**

- `load_dotenv()` does not override variables that are already set in the environment (default `override=False`), so real env vars win as required. I kept the defaults only as a local-dev convenience.
- Plain `def` endpoints with a module-level `MongoClient`: FastAPI runs them in a thread pool and `MongoClient` is thread-safe and pooled, so there is no need to switch to async/Motor.
- `doc.pop("_id")` after `insert_one` (the driver mutates the dict by adding `_id`) is correct for hiding the id; I replaced it with a serializer so it cannot be forgotten.
